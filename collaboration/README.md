# Shared boards

Run `npm run build && npm run dev` for the local frontend at http://127.0.0.1:4387. Configure your own Convex development project with `npx convex dev`; subsequent backend updates can deploy with `npx convex dev --once`. See the [root setup guide](../README.md) for environment configuration.

## Accounts and access

- Convex Auth v2 manages username/password accounts, sessions, password hashing and login rate limiting. Email verification/recovery requires an email domain and is not configured. Users should retain their passwords.
- The home shows owned and shared boards, search, creation and rename. Previews derive from saved node layout. Board ownership remains individual.
- Owners add existing accounts by username as editors or viewers. Invite links allow either account acceptance or named guest access. Guest sessions last 24 hours; links can be reopened for a new session.
- Links use random 256-bit tokens, stored only as SHA-256 hashes. Link membership is separate from direct membership: revocation and permission changes apply to people who have already joined. Removing a direct member does not remove access they separately received through an active link.
- Every board query and mutation enforces access on the server. Viewers cannot edit, send, invoke local AI endpoints or change sharing. Owners alone manage sharing. Clients hide editing controls and react to permission changes.
- The former auto-grant development bridge is disabled unless `ENABLE_DEVELOPMENT_BRIDGE=true` is explicitly set. The local server no longer issues development identities. An existing signed development cookie permits an explicit “Add to my boards” migration after sign-in. Migration preserves board data, moves ownership, and removes development memberships. It never silently claims the user's workspace into a test account.
- The frontend remains loopback-only. Invite links function in browsers that can reach that frontend. Deploy the frontend to an HTTPS host before inviting people on other devices. Do not expose the legacy migration bridge publicly; remove it after migration.

## Team workspaces

The home workspace switcher lists personal and team spaces. Users create a team, add existing accounts by username, and manage members from the team header. All team members may create and edit team boards. Team owners manage names/members; each board retains its individual owner and billing attribution. Board owners can move boards between their personal space and a team they belong to. Removing membership revokes team-derived access, but preserves separately owned boards, direct board membership and active board-link grants. Team invitation email and team guest links are not implemented; board guest links still work.

## Shared editing and AI

- Individual node rows and Yjs documents merge concurrent body, title and composer edits. Metadata changes patch individual fields; never replace the board with a stale snapshot.
- Per-field editing leases expire after 15 seconds and renew every four seconds. Blur flushes changes before releasing the lease. Send is allowed while the sender edits. It is blocked while another distinct person edits any field on the same node; multiple tabs from one account count as one person.
- Send atomically checks leases, acknowledged document version, active generation and idempotent request ID. It freezes the prompt, history and directional context. A draft epoch rejects late edits to a sent prompt.
- Scheduled Convex actions use only `gpt-5.4-mini`. Stream chunks persist approximately every 100ms and remain available if the initiator closes their browser. Automatic titles preserve manual titles.
- `billedUserId` comes from the board owner. Token usage is recorded; actual credit charges are not implemented.
- Activity badges and card outlines show active editors. Full live cursors/remote selections remain future work.
- Text undo is scoped to local Yjs edits. Canvas Command/Ctrl+Z restores locally deleted nodes and their incoming/outgoing context connections; Shift+Command/Ctrl+Z redoes deletion. The session keeps up to 70 deletions. Restoration retains canonical Yjs text, media references, transcript, and frozen context snapshots, merges connections into current destination rows, and skips destinations still deleted. Whole-board snapshot undo remains disabled.
- Navigation flushes acknowledged edits. Disconnection locks editing/Send; rejected changes are retained in `branch-unsynced-<boardId>` for recovery.

## Chat reading views

Canvas chats start as compact previews with opaque surfaces and fading text; expanded canvas transcripts cap at 480px and scroll internally; expansion and the right-side chat panel are local view preferences. The panel moves the existing card DOM instead of copying its composer. Both views use the same Yjs draft, document version, editing leases, Send mutation, and streamed messages. Independent people can work in different chats concurrently; another person editing the same chat still blocks Send. New idea batches are arranged horizontally. Unconfigured chats default to high reasoning; explicit thinking/speed choices remain respected. Replies prioritize concrete examples over lengthy generic coverage. Markdown is rendered with Marked and sanitized with DOMPurify.

## Remaining work

Email recovery, billing and full cursor presence are not implemented. New uploads are stored in board-scoped Convex storage (25 MB per file), with a local IndexedDB preview cache. File upload, registration and retrieval require board access; only editors upload. PDF and supported image bytes are included as typed Responses API inputs, with a 40 MB total local-file limit per Send. Older device-only files need Enable chat context on their source card and an explicit refresh of existing context references. Missing or unsupported file context blocks Send instead of silently falling back to a filename. Storage URLs are bearer URLs, so already-issued URLs are not revoked by membership removal. Storage cleanup/retention is not automated. Websites provide URLs plus shared, inline perspective notes. Chat runs enable OpenAI hosted web_search with gpt-5.4-mini, require a lookup when URLs are supplied, and store clickable inline citations in the final reply. Page access happens at send time, not when pasting a card; blocked/private pages may remain unavailable. Notes remain labeled collaborator perspective, separate from retrieved facts. Search tool charges are additional to model tokens. Existing attached snapshots only change on explicit refresh. Public YouTube captions are retrieved by the authorized local `/api/transcript` endpoint, cached for one hour and stored with the source. Send resolves pending/legacy link-only video bindings before freezing the transcript; existing completed transcript snapshots are never refreshed implicitly. Missing/restricted captions leave the draft intact with a retry/detach error. No YouTube API key, cookies, video download or audio transcription is used. Move/resize sync on release. Title and idea-expansion endpoints still run on the local server with board authorization; move these into owner-attributed server runs before billing. Development-sized board queries and CRDT documents need pagination and compaction before scale.

## Secrets and validation

The approved OpenAI key and development bridge secret remain server-only. Root `.env.local` is Git-ignored. Never print credentials, auth tokens or guest capabilities.

`npm test` exercises context inheritance plus real Convex Auth signup/signin, account isolation, viewer/editor enforcement, guest and account link revocation, legacy migration, Yjs merge, distinct-person Send gating, stale drafts and owner attribution. The Vitest WASM loader matches Convex's compiled-module behavior for the real password hashing implementation. `npm run typecheck` checks the backend. Browser checks cover sign-up, board creation, editing, shared AI, library previews and guest view-only access.

## Profiles and responsibilities

The dashboard and Account → Edit profile open the same compact profile dialog, which updates the display name, color, and a 4,000-character personal background. Blobz (`@blobz/avatar-core`) renders name-seeded avatars locally across accounts, member lists, editing presence, and attributed content. No hosted avatar service is used. Older unattributed messages keep their original presentation.

Team membership supports a 1,000-character role/responsibility description, separate from access permissions. The board's People control lists direct, team, and active invite-link participants and supports board-specific overrides. People may edit their own responsibilities; owners may edit their members' responsibilities. Overrides never grant board access, and people without current access are excluded from model context.

Send snapshots the sender's background and current project responsibilities atomically with prompt/context. Local chat and idea expansion resolve the same context server-side after authorization. Only the sender's background is included, never every teammate's private background. Responses on shared boards can reflect the sender's background; the profile editor explains this. Saved runs retain their frozen context after profile or role edits. Profile fields are absent from public membership responses except name/color.

## Context viewers and validation

PDFs render locally with PDF.js in `app/pdf-viewer.js`: page navigation, fit/zoom, full screen, download, selectable page text and readable load errors. `npm run build` copies the library worker, fonts, CMaps and WASM into ignored `app/pdfjs/`. Image previews preserve their aspect ratio; YouTube uses an embedded player with transcript loading/ready/error states, retry and an on-card timestamped transcript inspector. Captions retain their language (English preferred, original language otherwise). Retrieval accepts only validated video IDs, is bounded to four concurrent requests and a 64-entry cache, and rejects empty transcripts or more than 120,000 characters rather than silently truncating. Shared Send allows up to eight newly fetched transcripts and limits hydrated text to 300,000 characters; transcripts are untrusted source data, never instructions. Caption-backed questions do not force unrelated web searches. Replies may cite clickable timestamp links, but captions do not describe unseen visual content. Websites still use hosted web search at Send; they do not store scraped content.

The local and shared paths use the same immutable context resolver. Distinct excerpts/revisions survive deduplication, disabled sources omit attachments, and source-only branches remain isolated. File handles are authorized and resolved when Send atomically freezes a run; subsequent source edits do not rewrite it. `collaboration/context-input.cjs` supplies actual `input_image`/`input_file` parts to Responses instead of stringifying metadata. File storage links are excluded from automatic web-search triggering.

## Goal-driven research agents and canvas tools

Create a research agent with the lightning control on a source, or switch a chat from Chat to Agent in its composer. Named Blobz avatars identify each agent. The goal, live research stage and Stop control stay on the card. Only `gpt-5.4-mini` is used. Agents run three bounded Responses passes (discover, verify, synthesize), checkpointing encrypted reasoning, tool outputs and input between scheduled actions. An atomic claim prevents duplicate workers. Runs retain owner attribution, frozen input and aggregate token usage. Closing the initiating tab does not stop the job. Stop cancels future checkpoints, text writes and canvas tools; an already-running provider request may continue until its response/timeout.

Shared chats and agents can call `create_node` to make notes, website cards and draft chat branches. The tool never starts another run, edits existing content or reads unrelated nodes. Creation revalidates the initiator’s current board access and the origin’s active run, uses idempotent call IDs, and caps generated result nodes at five per run. Chat branches freeze their parent transcript at the tool call, with inherited context. Up to twelve unique discovered research sources appear as compact URL cards behind the agent, attached as provenance; they do not store extracted website content or alter the active run’s frozen input. Source links can be discovered or cited without proving the full page was accessible; the answer must report access limitations.

Generated cards share a visible group and use `app/auto-layout.js` rectangle packing on the server and rendered measurements in the browser. Existing cards stay in place; generated cards move out of collisions, including after their content grows. Per-card geometry updates use the existing patch path. Agent activity animates only while running and respects reduced motion. These features use the shared-board Send path; the legacy `/api/chat` endpoint remains a single-response compatibility endpoint without canvas tools.

Agent research sources fold by default into a counted paper stack above and behind their agent. Expand/Collapse is a keyboard-accessible local reading preference, available to viewers, and does not rewrite the source snapshots or positions. Hidden source cards and their wires do not enlarge Fit or the group frame. Dragging the agent or moving its grip with arrow keys translates its generated source/result group together; Escape restores each original position. Remote subscriptions preserve all dragged members, including new sources arriving mid-drag. Geometry is explicitly patched on release so stream subscriptions cannot swallow the saved movement. The group frame includes title rails and the source stack with 48px padding.

The compact context presentation is now a small source-node list to the left of the agent. Each row exposes a measured blue port so existing context wires retain their shared geometry and generation-only flow animation. The agent identity includes a workspace collapse control: it hides source/result cards and the transcript/composer, leaving the agent identity/status. Expanding restores the workspace. Collision clearance treats the padded workspace as one rectangle and translates all generated members together, including after drag release and content growth.

## Link preview gestures

Inline message links open a preview beside their source, expanding from the link on pointer clicks (280 ms); keyboard and reduced-motion users get immediate placement. Dragging keeps the compact highlighted link under the pointer, then expands it into a node at the release position with the pipe following; Escape cancels. YouTube links retain the player. Preview nodes persist `previewOrigin` metadata identifying source node, message, URL, and repeated-link occurrence. This draws a static blue pipe from the rendered link to the preview input without adding AI context. Missing or clipped links do not supply wire endpoints. Modified clicks and explicit browser fallback links retain browser behavior. Website nodes offer a local “Preview not loading?” fallback and retry; browser-enforced framing restrictions cannot be overridden, and iframe load events do not prove successful rendering.

## Sharing dialog

Share opens a compact access dialog from both the canvas and board library. Owners add existing Branch usernames, change direct members between Viewer and Editor, and remove direct grants. Team access is shown separately. General access can be Restricted or Anyone with the link; switching to Restricted atomically revokes all invite links and their joined users, without removing direct or team grants. Changing the general link role updates all live links atomically. Owner membership cannot be downgraded.

Copy link copies the board URL while Restricted. With link access enabled, it reuses a live invite created in the current browser session, or creates a new invite if no token is available locally. Tokens remain hashed on the server; the current invite is cached in sessionStorage, checked against live link IDs before reuse, and removed when restricting access. Other valid invites stay active until Restricted is selected. Clipboard failures expose a selectable URL. No email notification is sent. Localhost links still require access to the same frontend host.

Sharing has its own error boundary so query failures cannot disconnect the canvas. Teammate suggestions are optional and cannot prevent opening the dialog. Deploy `sharing:teammates`, `sharing:setGeneralAccess`, and `sharing:changeMemberRole` with the frontend changes before using all sharing controls.

## Work and workspace navigation

Account → My work and the dashboard's View my work show all owned boards across personal and team workspaces, with workspace labels and existing board actions. The account entry also returns from the canvas after disconnecting shared editing. The personal workspace lists boards without a team; team selections list that team's boards. Workspace dropdown → View all workspaces opens a searchable directory with board/member counts, workspace navigation, personal profile editing, and team management/details using the existing owner/member permissions. Team owners can rename teams and manage members; members can inspect the roster and update their own responsibilities. No new backend endpoints are required.

## Workspace settings and board access

Workspace settings are available from the directory, team header, and the board owner's Share dialog when they are a workspace member. Owners edit the workspace name/description and add or remove members. Members can edit their own responsibilities and leave; owners cannot leave. Every member inherits editing access to existing and future workspace boards. Direct board invitations and link grants remain separate: a direct Viewer invitation does not downgrade inherited Editor access, and removing a direct invitation does not revoke workspace access. The Share dialog explains this distinction.

Deleting a workspace requires owner authorization and an exact name confirmation. A single mutation moves all boards (including archived boards) into their individual owners' personal spaces, removes workspace memberships/invites, and deletes the workspace. Board content, owner/billing attribution, direct invitations, and board links are preserved. The UI explains these consequences before confirmation. The personal workspace itself is the account's default container, not a deletable team record.

Personal libraries also show individually accessible boards from workspaces the user has not joined (or has left). This keeps single-board invitations and retained ownership discoverable without exposing the rest of that workspace. Deploy the updated schema, teams functions, and sharing settings query together before using this frontend. Validation includes owner-only settings/deletion, inherited access removal, ownership preservation, explicit invitation/link preservation, and leaving a workspace.
